# Architecture and expansion

The project separates the component catalogue, mesh generation, placement, first-person controller, world presentation, persistence, and interface. GDScript and built-in Godot features keep the dependency surface small.

| Module | Responsibility |
| --- | --- |
| `src/main.gd` | Scene assembly, input shortcuts, save/load, graphics settings, autosave |
| `src/game_mode.gd` | Shared Creative/Survival mode, stable save names, Creative flight permission |
| `src/building/catalogue.gd` | Stable component IDs, dimensions, text, resource costs, connection sockets |
| `src/building/geometry.gd` | Shared procedural mesh recipes, materials, primitive and convex collisions |
| `src/building/foundation_geometry.gd` | Distinct plinth, paving, terrace, podium and stair-support geometry |
| `src/building/sculpture_geometry.gd` | Shared carved human, horse and lion meshes with simple gameplay colliders |
| `src/building/piece.gd` | Placed component identity, serialization, transformed sockets |
| `src/building/snap_solver.gd` | Placement and connector math, independent of rendering |
| `src/building/corner_joints.gd` | Indexed matching endpoints, right-angle join directions, corner occupancy |
| `src/building/stack_plan.gd` | Pure look-axis selection and repeat spacing, including rotated module axes |
| `src/building/builder.gd` | Preview, physics validation, placement/demolition, command history |
| `src/building/resources.gd` | Unlimited creative materials and a small future inventory seam |

## Component contract

Coordinates are metres. Each component's origin is at the centre of its bottom. Catalogue `size` describes the default module. `piece_size(id, length)` supplies the actual logical bounds for adjustable spans; each placed component carries `span_length`, defaulting to four metres. Hover frames use fitted mesh bounds. Collision geometry defines solid space separately, which is essential for walk-through arches and visually detailed columns.

Connection sockets have a local position, outward normal, and family. Stack sockets connect upward support to downward attachment. Floor sockets join foundation edges. Span sockets join bays and beams. Straight connections match families and opposite normals after applying the player's chosen rotation. Supported matching profiles also accept perpendicular span normals for 90° corners. A component may have multiple downward anchors; T cycles them and selects the attachment end of a corner. Rotation and height offsets are independent of the catalogue.

`FOUNDATION_KINDS` shares foundation socket rules. Structural modules use flush full-footprint ashlar faces and 0.4 m courses: one course for Foundation, two for Raised terrace, five for Temple podium. Repetition on X/Z/Y therefore forms continuous masonry without inset belts or projecting mouldings. Decorative paving retains its border and diamond patterns and uses one full-height walkable collider. Stable IDs, original footprints and top heights preserve saved placements. Floor sockets align bases on four-metre bays; top sockets use the existing two-metre support lattice. Tall side hits still find base-aligned foundation bays.

Temple stairs fit foundation side landings in `SnapSolver.landing_stairs`: the aimed edge determines yaw, the platform's world top determines total rise from ground level, and the run uses 0.5 m treads with risers at most 0.2 m. Only candidates on the aimed side are returned, with no short-flight fallback on blocked landings. Manual elevation or disabled sockets bypass fitting. `BuildPiece.stair_rise` defaults to the original 0.8 m; optional validated `rise` metadata preserves fitted geometry through placement, undo/redo, save/load and stack copies. Recipe caches, collision queries, logical bounds, sockets and stack spacing include the fitted rise. The top support socket sits on the actual upper tread. Old records without `rise` reconstruct unchanged. `tests/modular_foundations.gd` exercises all foundation axes and rotations, fitted landings on all four sides, offset and stacked heights, real camera/click placement, walking onto a podium, history/save/copy preservation and invalid metadata.

`PIECES` now contains the 39 components offered in the library. Five separate column parts, four retired right roof slopes and the original whole roof remain in `LEGACY_PIECES`, and `get_piece` resolves both lists so version 1 saves, geometry and history remain valid. `LEGACY_REPLACEMENTS` maps retired column parts to complete columns and the original whole roof to a left half during hotbar load. Library previews also normalize a legacy selection before accessing a card; existing placed parts are never converted or moved. The Foundations filter groups the six foundation kinds and temple steps; Roofs offers four modular slopes, a flat cover and two hollow domes. `tests/catalogue_cleanup.gd` checks the reduced library, legacy world round-trips and hotbar migration, continuous podium faces, recessed staggered joints, preserved mesh bounds, and column placement. Mesh audits include the legacy list.

### Column layout guides

`column_layout.gd` provides the standard four-metre column grid on upward foundation faces. The first column uses four-metre bay centres within the foundation; later columns inherit a compatible-height complete column's phase across connected coplanar foundation rectangles. The platform frame controls orientation independently of decorative column rotation. Disconnected platforms, different support elevations, skewed foundation frames and different-height columns cannot shift that origin. The chosen centre remains inside the aimed foundation. Layout mode returns only the nearest marked candidate, so collision rejection cannot quietly fall back to an incompatible half-metre position. Alt, disabled grid/sockets and manual elevation retain ordinary placement. A small nearby guide grid draws centre rings/crosses and dashed lines at the platform surface, clearing on other placement modes, empty hands and pause. Guides are temporary meshes, never saved or collidable.

Entablatures aimed at a complete column top attach their negative end by default when the anchor is automatic. Explicit T anchors remain available. Existing fitting against support tops and span endpoints, real collision checks and derived corner joins continue to handle closing rings. The HUD identifies four-metre column spacing and beam-end attachment. `tests/column_layout.gd` covers approximate aims, rotated and off-grid platforms, connected versus separate layouts, height compatibility, native camera/click placement, override/cleanup behavior, history/save preservation and complete four-sided entablature rings with both ends of the last side joined.

### Modular roofs

The library offers one full and one half slope per material: full slopes span 4 × 4 m and rise 2.4 m; half slopes span 2 × 4 m and rise 1.2 m. R twice turns either into the opposite side. `ROOF_KINDS` still contains all eight supported IDs, including the four right-facing legacy variants. Existing saved right slopes keep their geometry; hotbar assignments migrate to the corresponding left ID with its neutral display name. Middle-click picking also rotates the replacement 180° to preserve the saved slope orientation. `roof_geometry.gd` builds a thin convex tile shell at pitch 0.6 with non-solid tile courses and cover ribs (terracotta) or staggered broad slab panels with recessed joints (stone), keeping the room empty. Detail stays within module X/Z planes so adjacent bays do not overlap or drift. Logical roof spans control horizontal stack spacing. The original solid `roof` remains in legacy geometry; library/hotbar migration offers `roof_left_half` instead.

`roof_rake` sockets encode low/high cross-roof endpoints; `roof_run` sockets repeat the same profile in four-metre depth bays. Gable socket families distinguish full and half widths, with a world-space uphill direction check that also applies to depth sockets. This permits rotated opposite slopes and rejects mismatched pitches. Matching gable sockets attach slopes behind left/right pediments and small halves at ±1 m behind crowns or the original small pediment, in either construction order. Top-surface hits near roof edges also permit rake/run connections instead of stacking a roof above its ridge. Gable sockets use the wall's centre construction plane so building depths remain multiples of four metres. Derived roof join flags cut each attached end shell back by 0.35 m to the gable's inside face, leaving its cornice and finial clear; internal roof bays keep full depth. When placing a gable after a roof, only the matching fitted roof partners are excluded from the pre-commit collision query because those ends trim on commit. Normal obstacles still block placement. Removing a gable restores its roof end; preview, history, saves and stack copies derive all end treatment from sockets rather than stored links.

`tests/modular_roofs.gd` checks every profile's pitch/ridge/depth and rotated gable joins, reverse gable attachment, all trimmed mesh variants, an empty attic and solid tile shell, true seam continuity, a complete 20 × 12 m building including ridge finials, native placement/picking, history/save preservation, stack depth/cutback behavior and legacy whole-roof migration. `--capture /tmp/roofs.png --roofs` renders the complete example; adding `--catalogue` shows the Roofs library.

### Hollow stone domes

`DOME_KINDS` contains 4 × 4 × 2.4 m and 8 × 8 × 4.4 m roofs. `dome_geometry.gd` revolves a closed inner/outer hemisphere and short drum above a square-to-circular coping ring. Convex annular sectors preserve the open interior; a small overlapping crown collider closes the pole where sector hulls become degenerate. All visible surfaces use the selected stone shader. Domes remain separate from pitched `ROOF_KINDS`, whose canonical `roof_profile` shares socket families and gable trimming between clay and stone.

Dome downward sockets include centre, four edges, and four corners. The default wall/beam anchor is an edge; a matching contiguous collinear run of total dome width centres it over the complete run, including two-bay eight-metre walls. Rotation chooses the attached side, and explicit anchor cycling bypasses automatic centring. Foundation support uses the centre. All connections and geometry derive from ordinary component records, preserving material, history, picking, and stack behavior.

`tests/stone_and_domes.gd` checks all stone finishes, slab joints, mixed clay/stone connections, gable cutbacks, rotated complete rooms, hollow collision, solid crown/corners, inner/outer surfaces, native dome placement, save/history, picking, and stacking. `--capture /tmp/domes.png --domes` renders both dome sizes; `--capture /tmp/stone-roofs.png --stone-roofs --marble` renders a marble slab roof.

### Modular pediments and sculpture

`PEDIMENT_KINDS` adds four-metre left/right triangular slopes, a crown, backing, and a base cornice. The rake pitch is 0.6, matching the original pediment. Each slope rises 2.4 m; the crown rises 1.2 m. `pediment_rake` builds layered mouldings with vertical-cut ends. Exposed eaves clip at y = 0; connected low ends restore the small missing moulding wedges and continue their dentils. `CornerJoints` indexes raking sockets and derives endpoint flags, so placement previews, additions/removals, undo/redo and load all reconstruct the profile. The completions are decorative trim, matching the existing non-solid dentils; the clipped solid bodies remain unchanged so backing courses and recessed sculpture do not need collision exemptions. Endpoints and module dimensions retain their original positions. Joined recipe variants are cached. `tests/pediment_seams.gd` casts visibility rays through both slope seams and crown ends, audits every profile variant, and checks rotated placement, previews, removal, history and load. Dedicated `pediment_rake` sockets encode the height change, while `pediment_course` sockets extend horizontal backing and base courses. Ordinary top/underside stacking fills the courses below the rake. The original `pediment` ID and geometry stay compatible.

Backing lies at local z = −0.23 with 0.16 m thickness, leaving room before the mouldings. `sculpture` sockets position shallow carvings at z = 0.09. Optional socket `accepts` metadata restricts the low corners to reclining figures and reserves off-centre backing attachments for standing statues. `world_sockets` preserves this metadata. Recess sockets require an actual front-face hit; they cannot attach through the rear or from a perpendicular side face. Two opposite input normals let figures rotate 180° within the same recess. No target body is exempted from physics validation.

`sculpture_geometry.gd` makes draped standing and reclining human figures and a posed horse from closed lathed, ellipsoidal and extruded details. Each recipe bakes its visible parts into one shared mesh, explicitly expanding indexed and unindexed source surfaces and transforming normals with the inverse transpose. Separate inexpensive colliders keep the carvings aimable and prevent occupied recesses from overlapping. All sculpture follows normal materials, hotbar assignment, history, stacking, and version 1 save records.

`tests/pediments.gd` checks rotated and reversed rake joins, full twenty-metre assembly collisions, real camera/click continuation and crown placement, front-only sculpture attachment in both orientations, corner sculpture vertex clearance, complete visible sculpture geometry, undo/redo, save/load, and catalogue availability. `--capture /tmp/pediments.png --pediments` renders the example assembly without modifying the player's save.

### Automatic mitres

`BuildCatalogue.MITRE_KINDS` identifies walls, entablatures, cornices, and balustrades. Each defaults to a logical four-metre centre-line span and accepts half-metre lengths from 0.5 to 8 m. `CornerJoints` indexes its two bottom endpoints by position and detects a same-profile perpendicular neighbor at either end. Vertical alignment is therefore checked even when profiles have several courses. A third run at an occupied corner is rejected rather than forced into a broken T junction.

For a joined end at local X = ±length/2, the profile is cut by the plane `±x + turn*z <= length/2`. The adjoining piece uses the opposite half-plane. Courses extend outside the logical endpoint before clipping, filling the exterior corner while leaving no overlapping interior material. Geometry recipes bake clipped boxes into closed convex prisms with corresponding colliders. Dentils continue around the outer mouldings, and balustrade end posts become two halves of one shared square corner post. Primitive and clipped mesh faces use Godot's clockwise front-face convention.

Derived recipe variants are shared and cached by kind, span length, and left/right turn. Straight recipes regenerate masonry courses, dentils, and balusters at their original sizes instead of scaling ornaments. The ghost uses the same recipe as the finished piece, and hover bounds use the actual fitted mesh extent. Placement excludes only the confirmed matching corner partners, allowing a final side to close at both ends while retaining overlap checks against other objects and the player.

The endpoint index and fitted geometry are rebuilt on addition, demolition, undo/redo, and world restoration. Join links are not stored in JSON: existing component IDs, positions, materials, and rotations remain the save contract, including version 1 worlds. A validated optional `length` field records nonstandard spans; omitted lengths mean four metres. Existing saved positions are never migrated or moved. This also avoids stale links when restoring a deleted neighbor. Imported replacement art will need equivalent end profiles or a dedicated join mesh; arbitrary roof hips, arches, mixed profiles, and T junctions are not assumed to be mitre-compatible.

### Placement grid and fitting

`SnapSolver.candidates` returns nearby socket placements on the raycast component in distance order plus a surface-grid fallback. The hit normal filters attachment types: upper faces accept upward stack sockets, undersides accept downward stack sockets, and side faces accept horizontal sockets that do not face away from the raycast face. Perpendicular span sockets remain available for mitred corners along a broad side. Underside attachment uses the selected component's top anchor for every component kind. Ground hits use only the ground grid; nearby components cannot steal the preview. `solve` remains the pure first-candidate API. The builder tests candidates against actual solid geometry and uses the nearest clear placement on that same aimed component and face, keeping the nearest blocked preview when none fit. A snapped target is not exempted from collision; only confirmed matching mitre partners receive the corner exception. Collision contact tolerance is a fixed 3 mm per side rather than a percentage of piece dimensions.

The half-metre grid uses the aimed component's transform, or the selected rotation at the world origin on open ground. Heights retain the exact hit surface value. Linear spans align an endpoint to the grid, allowing quarter-metre centre pivots for odd half-metre lengths without drifting their endpoints. Side placement uses the sum of absolute rotated footprint axes; rounding cannot project a component back through the aimed face.

With automatic length selected (`span_length == 0` on the builder), a snapped end scans matching endpoints and aligned column/pedestal tops along its outgoing axis and shortens the default bay to the next grid-aligned gap. Both straight infills and closing mitres use this rule, retaining the anchored end and the chosen rotation. Manual lengths bypass fitting; height offsets, socket disabling, and Alt bypass socket fitting as well. Comma/period set a fixed length, slash resets Auto, and changing a slot resets to Auto. The ghost and finished component share length-specific recipes, sockets, joins, physics, serialization, and stack spacing. A recessed cornice backing keeps the dentil course physically continuous and aimable.

`tests/face_placement.gd` covers all 39 library kinds near upper side edges, rotated short components and opposite ends inside the snap radius, neighbor and ground rejection, top/underside restrictions, generic underside attachment, and actual camera-ray/left-click placement while switching faces or aiming at a blocked end.

`tests/layout.gd` exercises full column-supported beam rectangles, short and mixed-span rectangular closure in both directions and rotated frames, all components' surface grids, span endpoint alignment, varied-length mesh audits, real camera placement, blocked candidates, strict contact tolerance, keyboard controls, save validation, legacy compatibility, and fitted history and stacking.

To add a component:

1. Add an entry with a new, stable `id`, metre dimensions, group, and description in `catalogue.gd`.
2. Add a mesh recipe in `geometry.gd`, with useful colliders around its solid sections.
3. Add special sockets if the default top/bottom connections are insufficient.
4. Add its library silhouette in `component_icon.gd` and exercise it in the gameplay checks.

Mesh resources are shared across instances. Replacing a procedural recipe with a `PackedScene` or imported glTF model can preserve the same ID, origin, dimensions, collision semantics, and socket contract. Keep visuals separate from socket data so improved artwork does not change saved placements.

Opaque procedural geometry uses clockwise front faces with outward normals and closed solids, leaving ordinary back-face culling enabled. `_triangle` enforces winding against the supplied normals and skips zero-area faces. Lathed profiles receive end caps, fluted shafts use normals derived from the fluted surface, and extruded polygons normalize their point order before building front, back, and edge faces. Corinthian leaves have thickness and closed edges. The urn profile turns inward at the rim and finishes at a bowl floor; its mouth remains hollow rather than capped across the opening. `tests/meshes.gd` audits all catalogue meshes and corner variants for orientation, closure, valid normals, and degeneracy, with visibility rays for intentional openings.

The hotbar contains nine editable building slots and one fixed **− / Stack tool** slot. `DEFAULT_SLOT` is the ordinary ninth building slot, initially empty but fully assignable; there is no dedicated Inspect slot or 0 shortcut. Empty slots use an empty component ID, and Stack uses a reserved non-component ID. `is_building` requires a populated editable slot; `is_empty_handed` covers selected empty slots. Empty cells have no icon or caption. Empty-handed preview hides the placement ghost and marker but raycasts the same first-hit collision layers and reach as placement, drawing an outline on an aimed component. The component name and removal hint appear while a target is present; the crosshair stays visible throughout gameplay. Right-click refreshes the camera ray and removes that component through normal history/refund handling; left-click does nothing. Paused players and the idle Stack tool cannot delete world components. `tests/empty_slot_deletion.gd` verifies all nine slots, native input, undo/redo, stale-target prevention, reach, blockers and menu/library safety.

Middle-click invokes `pick_aimed_component` before Stack input routing. It raycasts the current camera with placement reach and first-hit collision layers, searches the nine editable slots (preferring the currently equipped match), or replaces the selected editable assignment. From Stack, a missing component uses `last_build_slot`. Picking copies the stone finish, cancels active stacking through normal slot selection, refreshes the ghost and UI, and marks preferences dirty; it never edits world geometry or history. Paused input and missing/out-of-range hits leave the hotbar alone. Legacy separate column parts pick their complete-column library replacements. `tests/pick_component.gd` exercises native middle-click dispatch, matching and duplicate slots, replacement, empty hands, Stack selection, finish, persistence, fresh aim, reach and menu safety.

**E** toggles the creative library; B and Tab remain aliases. Its component cards and visible hotbar use `ComponentSlot`, a native draggable Button with `_get_drag_data`, `_can_drop_data`, and `_drop_data`. Library drags copy a stable component ID into a chosen slot; hotbar drags swap assignments, including moving a filled slot into an empty one. Drop validation checks IDs, source slots, and stale data. `assign_slot` and `swap_slots` protect the fixed Stack tool slot, refresh the equipped ghost when necessary, emit change signals to update the menu, and mark preferences dirty for autosaving. The library remains open during assignment and pauses player movement. Page Up/Down adjust piece height, with Q retained as a lower-piece alias. `tests/inventory.gd` drives actual pointer drags and keyboard events, including save/load of customized slots.

Dragging an editable hotbar component outside the entire hotbar and releasing clears its assignment. `ComponentSlot` records the source kind and actual mouse-release position in canvas coordinates, then handles `NOTIFICATION_DRAG_END` only for an unsuccessful external drop while the source is still visible and unchanged. Escape cancellation, dropping onto fixed slots, and releasing between slots preserve the source. Library drags never remove assignments. `clear_slot` and `clear_hotbar` protect fixed slots, refresh selected ghosts, emit UI changes, and mark preferences dirty without editing the building or its history. The library provides a one-click **Clear slots 1–9** button, disabled when those slots are already empty. The loader accepts empty strings in editable slots and keeps existing legacy-column migration. Library previews fall back to a valid component when the equipped slot is empty. `tests/empty_hotbar.gd` drives native drag-out removal, swaps into blanks, protected targets, cancellation, button clearing, safe empty-handed actions, refilling, and empty/partial save round-trips.

The catalogue grid scrolls inside a fixed-height container as components are added; the hotbar remains visible underneath. The 3D preview adjusts its orthographic size for wide foundations without changing component geometry.

### Stack tool and grouped history

Equipping the dedicated tool slot (wheel, library hotbar, or minus key) routes left-click to raycast the first placed piece and enter live region selection; right-click locks the ending component. While choosing endpoints, left-click resets the first point and scrolling leaves the pending region unchanged. Once locked, scrolling changes the repeat count, left-click cancels, and right-click confirms. `StackPlan.select_between` includes component centres inside the union of both endpoints' logical bounds in the first endpoint's frame. Endpoints are always included; each member and the region receive outlines. The first hover uses a red surface overlay and outline, and the second uses green. Selected members have a subtle overlay, with muted red/green endpoint tints. Overlays preserve the original stone materials and any prior overlay, restore them when the hovered region changes or selection ends, and never affect copy validity materials or saved data. Selecting the same component twice produces a single-piece stack.

The builder keeps selected members, repeat count, and collision-free ghosts separate from `pieces`. `StackPlan` converts camera direction into the first member's local basis and picks its dominant signed axis. Single-piece spacing preserves foundation dimensions, actual mitre centre-line spans (including fitted lengths), and roof bays; other axes include visible bounds. Group spacing uses combined logical and visual bounds. Each repetition translates every member equally, retaining its basis, finish, and relative position. The repeat count is signed: positive follows the view axis, negative reverses it, and zero clears all ghosts. Ghost allocation and budgets use the absolute count; validation and confirmation accept either sign. The HUD shows the absolute quantity and direction, including Up/Down. Vertical pitch selects the Y axis using the same dominant-axis rule as horizontal placement. Counts are limited to 32 sets in either direction and 256 total preview components; selections larger than 256 cannot lock.

A virtual endpoint index includes the world and preview ghosts, whose temporary IDs are negative. Preview variants fit existing right-angle joins and reject third runs. Every copy uses normal placement checks against existing physics, the player, and construction limits. The world count limit covers the entire batch. Cached validation refreshes with direction, every selected member's transform, world count, or player movement; confirmation always rechecks physics. No preview enters world collision or serialization.

Left-click cancels and right-click confirms a locked selection. Confirmation assigns positive IDs only after all checks succeed, adds all copies, rebuilds joins once, and records one `batch_add` command. Undo/redo removes/restores all records and rebuilds connections once, preserving originals and composing with ordinary add/remove commands. Save version 1 remains unchanged: confirmed copies are ordinary piece records. Menu entry, slot changes, load, or deletion of any selected member discards pending state. The tool remains Creative-only. `tests/building_tools.gd` covers single-piece arrays, fitted corners, and history; `tests/group_stacks.gd` exercises actual two-point input, mixed and rotated selections, transform fidelity, atomic rejection, cache invalidation, member deletion, preview budgets, history, and persistence.

The display uses a 1920 × 1080 UI reference canvas and an initial 1600 × 900 window, both 16:9. `canvas_items` stretching with `expand` adapts to resized windows and native fullscreen dimensions without distorting the UI. F11 toggles fullscreen; GPU captures verified a 2560 × 1440 viewport. The HUD has ten 56 px icon cells with 32 px silhouettes and no permanent branding, resource, world-count, or footer panels. Building context shows the component name, stone/snap state, offsets and placement errors; empty-handed aiming shows the target name and removal hint. The HUD owns a mouse-ignoring, centred 48 px ColorRect using `crosshair.gdshader`. Its 36 px plus reads the screen texture per pixel, smoothly changing from white to black as background luminance increases. A one-pixel opposite outline prevents loss of contrast over middle grey. The transparent corners leave the scene untouched. Anchors keep it centred across resizing and canvas scaling; HUD visibility hides it in menus. GPU checks sample black, white, grey and split bright/dark backgrounds, exercise empty/build/Stack modes and resizing, and check transparency. H toggles an optional controls guide, off by default. Flight changes and successful autosaves do not emit toasts; manual saves and errors use a short notification. The library uses smaller cards and a compact hotbar while retaining native drag/drop behavior.

## Lighting and graphics

The default renderer is Godot's OpenGL Compatibility renderer. Simple, Balanced, and High change shadows and multisample antialiasing. The current world uses warm directional sunlight with shadows, a gentle opposing cool directional fill without shadows, cool ambient light, a dedicated sky shader, distance fog, stone shaders, and tiled roof geometry. The fill makes shaded relief readable without another shadow map. A persisted **Brightness in shade** setting controls ambient energy between 0.35 and 0.85 (default 0.58). Sun energy is balanced against that ambient level to preserve detail in bright stone. The catalogue uses the same warm-key/cool-fill approach in its own preview world. Terrain triangle order produces upward-facing normals.

`daylight_sky.gdshader` draws one bright solar disc directly from `EYEDIR` at full resolution, with a derivative-smoothed edge and a small additive halo. Both directional lights use `SKY_MODE_LIGHT_ONLY`; the sky receives only the real sun direction through a dedicated uniform. This avoids duplicate discs from fill lights and decouples solar brightness from the low direct-light energy used on pale stone. The visible sky does not sample the blurred radiance cubemap.

`SanctuaryWorld` stores daylight as a normalized `day_progress` and advances it over 1,200 seconds. The sun follows an east-to-west arc, with a 60-degree maximum elevation, from a low morning sun to the sunset horizon. Wrapping immediately restores morning; there is no night or fade. Sun orientation, direct-light color/energy, opposing fill direction, sky gradient, and fog color update together every 0.1 seconds and immediately on a wrap or restore. The smaller 128-pixel radiance map uses incremental processing. The shade brightness setting remains independent.

The main game loop advances daylight only while the player is active, pausing the clock in menus, settings, confirmations, and the library. Saves contain an optional `preferences.day_progress`; restore validates its type and range, and old saves default to morning. New sanctuaries reset to morning. `tests/daylight.gd` checks the sun arc, shader/light alignment, shade settings, sunset wrapping, large elapsed frames, update-rate consistency, invalid values, real play/pause behavior, and save migration. `--capture /tmp/sun.png --sun --day-progress 0.2` provides a reproducible render aimed at the sun for visual checks.

A graphics upgrade can switch to Forward+ in the Godot project or through `--rendering-method forward_plus`. That renderer requires newer hardware and should receive its own tuned environment. Introduce a separate lighting profile before adding SSAO, SDFGI, reflection probes, volumetric fog, or higher-resolution textures. Tone mapping, brightness, and shader results need visual verification after a renderer change. Keep a tested Compatibility profile for older machines.

Geometry, snapping, save data, and input do not depend on a rendering backend. Forward+ upgrades therefore do not require a rewrite of the building game. Additional material finishes should receive stable material IDs and a save-version migration when the current indexed representation becomes insufficient.

## Survival next

`GameModeState` defines Creative and Survival. Creative is the default and is the only available mode in this prototype; the menu labels Survival as Coming later. The player and resource ledger share the same mode instance. Mode is an optional saved preference so old worlds load in Creative. `SURVIVAL_AVAILABLE` remains false until the survival systems are ready.

Placement already asks `ResourceLedger` whether it can spend the catalogue's resource cost. Creative mode always succeeds. A future survival system can supply actual inventories and collection interactions through that seam.

The player recognizes two distinct Space presses within 300 ms to toggle Creative flight. Keyboard repeat events are ignored, a key release is required between presses, each pair is consumed once, and pausing or restoring the player clears partial gestures. Space still supplies ordinary jumping and upward flight input. Flight uses body yaw for level WASD movement and Space/Shift for vertical movement, independent of the viewing pitch. Shift retains sprint on foot, but flight ignores Shift as a speed modifier so it remains the descend key. Ctrl is reserved for shortcuts such as undo/redo and does not affect flight altitude. Both the Space gesture and the F shortcut use the same Creative-only flight toggle.

Flight approaches the requested world-space velocity with `Vector3.move_toward`, using 80 m/s² acceleration while steering and 40 m/s² braking after releasing input. At the normal 8 m/s maximum this produces roughly 0.2 seconds and less than one metre of coasting, while short taps build less momentum. Horizontal and vertical movement share the existing total speed cap. Turning the view during a coast preserves the original movement direction. Acceleration and braking use physics delta; `move_and_slide` resolves obstacles, and sanctuary bounds clear outward velocity. Deactivating the player clears velocity immediately, as do flight changes and save restoration. Walking retains its original acceleration, gravity, jumping, and stepping. `tests/flight_momentum.gd` exercises real controller movement, short and sustained input, vertical and diagonal flight, reversing, menu cancellation, wall/boundary stops, and coasting consistency at 30/60/120 physics ticks per second.

Before enabling survival, connect removal and undo/redo to inventory transactions, record resource changes in the same action as placement, and define what restoring a saved world does to inventory. The current undo/redo implementation is designed for unlimited creative resources. Gathering, tools, needs, health, recipes, and enemies are intentionally unimplemented.

## Persistence and limits

Save version 1 stores stable component IDs, unique integer instance IDs, stone finish, position, and Y rotation, plus player and hotbar preferences. Nonstandard linear spans include an optional validated half-metre `length`; older records keep their default dimensions. Loading validates the entire component list before replacing the live building. Save writes use a temporary file and preserve the preceding file as `.bak`.

The loader accepts original nine-slot bars, legacy ten-slot bars ending in Inspect, legacy eleven-slot bars with Inspect and Stack, and current ten-slot bars ending in the reserved Stack ID. It preserves all nine editable assignments, including blanks, and appends only Stack. Legacy Inspect selections move to an existing empty editable slot or the previous building slot if none is empty; legacy Stack index 10 maps to current index 9. The terminal Stack ID distinguishes current ten-slot saves from legacy Inspect bars. No save-version change or placed-component migration is needed.

The prototype allows up to 4,000 pieces, a 120 × 120 m construction region, and 40 m building height. These are guardrails rather than performance promises. Placement checks actual collider parts and scans nearby candidate sockets. Before supporting large cities, profile the target hardware and introduce a spatial index, collision-query caching, distant mesh merging, and scenery LOD. Imported high-detail geometry should have deliberately simple gameplay colliders.

Buildings do not require physical support and have no collapse simulation. This keeps composition flexible while the architecture system is being developed.

`tests/roof_rotation.gd` verifies 180-degree slopes on right pediments and crowns, rotated room frames, reverse gable placement, correctly oriented end cutbacks, legacy right-slope depth extensions, same-kind ridges, native R input and placement, save/load, and picking legacy slopes with equivalent rotation.

### Foundation perimeter wall placement

`wall_perimeter.gd` handles top-edge hits for all `WALL_KINDS` in default automatic-length/centre-anchor mode with grid and socket snapping enabled. It uses the connected coplanar foundation rectangles from `ColumnLayout.platform`, subtracts edges covered by neighbours, and merges exposed collinear runs. Selected rotation chooses the edge direction. A 0.7 m edge band activates fitting; internal foundation seams and skewed rotations keep ordinary placement. Source foundation height remains exact, including rotated/off-grid platforms.

Wall foot/coping centre lines sit 0.22 m inside the exposed edge, so the outer masonry is flush. Four-metre run bays retain their internal seams; only outer ends receive corner offsets. Convex corners shorten the first/last bay; concave corners extend it so the inset centre lines meet. A single four-metre run therefore fits a 3.56 m wall, while the two ends of an eight-metre run each fit 3.78 m. Returned perimeter candidates keep blocked edges blocked rather than jumping to another bay. Existing walls and foundation geometry are never migrated.

`BuildCatalogue.valid_span` accepts ordinary half-metre lengths and, for wall kinds only, lengths displaced by ±0.22/±0.44 m for these corner offsets. World-store validation and connection fitting share this rule; finite/range checks remain in force and unsupported quarter-metre spans remain invalid. The normal `length` save field, geometry cache, history and stack contracts preserve fitted walls. HUD lengths show up to two decimals.

`tests/wall_perimeter.gd` checks all wall/foundation combinations, rotations, top height, physical placement and save validation; connected bays, internal seams, partially covered edges and inward L corners; manual overrides; native four-sided room placement and exact outer footprint; and undo/redo/save/load. `--capture /tmp/wall-perimeter.png --wall-perimeter` shows the completed perimeter on courtyard paving.

### Window corner mouldings and forward sprint

The corner recipe baker preserves non-identity part bases instead of rebuilding rotated BoxMeshes as upright prisms. Pediment window rake mouldings sit inside their bay and retain their original meshes/transforms; axis-aligned masonry and corner profiles still undergo ordinary mitre clipping. Forward sprint recognizes a released/pressed W pair within 300 ms, ignoring keyboard repeat and consuming each pair once. Holding the second press latches sprint; forward release or backwards input clears it. Menus, library, focus loss, restore and flight changes reset partial gestures and active sprint. The multiplier is 1.8: 5→9 m/s on foot and 8→14.4 m/s in flight, with normalized diagonal movement and the existing flight acceleration/braking. Shift sprint on foot and Shift descent in flight remain available. Sprint state is transient and is never saved. `tests/sprint.gd` checks timing, repeats, consumed pairs, cancellation/reset cases, movement speeds, normalization, Shift compatibility, native W input with empty hands, release and coasting.

### Ceiling and pediment fitting

`ceiling_fit.gd` derives slab footprints from nearby pediment meshes. Only orthogonal gables at a slab perimeter and intersecting its 0–0.2 m vertical interval are eligible. Their projected bounds cut through to the outside edge, so recessed backing leaves no detached strip. Rectangle subtraction preserves uncovered portions of offset edge bays and handles multiple pediments on different edges. Unaligned gables, interior intersections and other component overlaps remain blocked.

`BuildPiece.ceiling_rects` is derived state; the saved position, rotation, normal sockets and four-metre stack spacing stay unchanged. Geometry and collision use identical fitted rectangles, with top slab joints clipped to each rectangle and closed edge faces. The preview cache is bounded to 128 variants. The builder fits normal and stack previews, reconfigures ceilings on connection refresh, and reconstructs cuts after restore/undo/redo/removal. Incoming gables exclude only ceiling partners whose perimeter footprint will be cut on commit. Other collision checks, including the player, remain active.

### Pediments at outer entablature corners

`pediment_fit.gd` finds the collinear entablature course below a modular gable and measures its actual mitred mesh extent. A shared horizontal affine mapping takes the run’s logical endpoints to its outer corners. Each slope, crown, backing and base receives its local portion of the same mapping, preserving continuous diagonal seams while retaining logical four-metre sockets, rise, roof sockets and saved coordinates. Straight beam ends without an overhang remain unchanged. The front/back depth is unchanged.

`BuildPiece.pediment_fit` is derived on connection refresh and applied equally to previews, rendering and collision queries. Box and convex collider dimensions are baked, avoiding nonuniform CollisionShape3D scaling. Ceiling subtraction measures the fitted gable footprint. Stack previews include planned supporting beams. A 0.16 m upper stone cap screens the maximum 0.15 m tile relief; crown-mounted finials receive a derived offset above that cap, preserving their saved pivots. Removing or rebuilding supporting corners updates the fit automatically.

### Ceiling preview performance

Ceiling fitting reuses each committed gable’s derived `pediment_fit` and a cached local mesh AABB. It rejects unrelated perimeter planes and vertical intervals before any supporting-beam calculation. Bounds are transformed directly, avoiding temporary collision shapes and repeated connection-index construction for every gable, candidate and frame. Planned stack pieces explicitly request a fresh fit; connection refresh updates committed fits before rebuilding ceilings. Incoming gables also use the cheap rejection before solving their proposed support fit.

In the isolated 94-piece temple profile, ceiling footprint fitting fell from 8.30 to 0.047 ms per call; native preview updates fell from 8.39–16.70 to 0.17–0.26 ms per call. These are local headless CPU measurements, not a guaranteed rendering frame rate. `tests/ceiling_performance.gd` compares reused and freshly solved footprints across all edge bays, checks world-edit invalidation, and times batches of real previews at three pediment/entablature aims with a generous 5 ms average ceiling. Existing ceiling, pediment, collision, save and stack tests verify the resulting behavior.

### Offset ceiling bays and existing-grid infill

Ceiling fitting supports a half-metre phase difference between existing ceiling tiles, the entablature and the roof grid. Gable and eave eligibility permits a perimeter offset up to 0.75 m while rejecting middle-of-panel intersections. Each roof constraint includes its actual, gable-trimmed depth interval. Coplanar adjacent intervals merge; ceiling boxes split only at relevant interval boundaries before clipping. This confines a roof’s cut to its own footprint, preserves uncovered panel portions during construction, and lets one ceiling span neighbouring roof-depth bays. Roof joint refresh precedes ceiling regeneration; stack previews derive planned roof trims from their shared connection index.

When aiming at an entablature, pediment or slope near existing ceiling panels, `SnapSolver.ceiling_infill` follows that ceiling course’s grid to fill the nearest missing bay. It preserves the chosen panel rotation and uses indexed occupied positions instead of scanning all pieces for every candidate. This also works when the aimed entablature top is hidden behind the roof. Existing placed tile coordinates remain unchanged.

`tests/offset_ceiling.gd` reproduces a 16 m square ring at support height 7.05 m, full opposed slopes, both pediments, and ceiling centres offset by 0.5 m in both axes. It fills all sixteen tiles in both construction orders on normal/rotated buildings, audits closed meshes, verifies finite roof depth and interval merging, and reproduces the reported camera’s actual preview and native click before history/save round-trips.
